# 具身采集 LMDB 数据格式

## 数据集边界

每个 `scene_<六位序号>_<十二位哈希>.lmdb/` 只包含一个成功场景、一个任务和一条轨迹。场景序号必须形成从零开始的连续前缀。

每个场景的对象总数由配置闭区间确定性采样，并完整写入场景静态定义。单目标任务允许包含不参与指令的干扰对象；分类和连续整理任务的 AST 会引用该场景中的全部对象。

数据集根目录的 `dataset.json` 保存 schema、主随机种子、兼容配置指纹和 Panda 资产指纹。`checkpoint.json` 保存已发布成功场景数和下一个序号，不保存任何失败轨迹。

## Named databases

- `meta/scene`：场景 ID、场景静态定义、任务 AST、规范指令、完整 MJCF、成功证据、配置快照、资产/配置哈希和软件版本。
- `meta/complete`：值为 `1` 时表示场景事务完整提交。
- `frames/<八位帧号>`：逐帧压缩记录。
- `index/summary`：帧数、逐帧编码摘要和 schema 版本。

复杂值使用 MessagePack 编码，NumPy 数组显式保存 dtype、shape 和连续字节，随后使用 Zstandard 无损压缩。每个 value envelope 带未压缩内容的 SHA-256。

## 帧结构

- `frame_index`、`simulation_time`、`phase`、`success_state`。
- `action`：末端位置/姿态误差、关节位置目标、夹爪宽度目标；实际 actuator control 和 force 位于机器人状态。
- `robot`：七关节 qpos/qvel/qacc、执行器控制/力、夹爪宽度，以及每个关节 frame 和末端 frame 的基座相对 pose、速度、加速度、局部 accelerometer 与 gyro。
- `objects`：所有对象的世界 pose、空间速度及形状、颜色、尺寸、质量、摩擦。
- `scene_description`：不含连续坐标的受控定性场景描述。
- `physics_state`：MuJoCo `mjSTATE_FULLPHYSICS` float64 状态，用于逐帧恢复。
- `cameras`：逐相机的 `K`、`T_world_camera`、`T_base_camera` 和所启用的视觉模态。
- `contacts`：开启接触传感器时的原始接触信息。
- `tactile`：开启接触传感器时的双指 `32×32×3` 三轴力图。接触位置相对各指尖 `tactile_site` 的中心与姿态投影到网格；通道固定为 `[normal, tangent_x, tangent_y]`，法向力非负，两个切向分量保留符号。

`HELD_BY` 是通过连续双指法向接触和实际抬升验证后的任务语义，不代表仿真中存在绑定约束。采集器不会修改自由物体位姿来跟随末端；一侧触觉为零的帧表示该侧当帧没有物理接触，不能单独构成成功抓取证据。

单位统一为 SI：位置为米、时间为秒、线速度为米每秒、线加速度为米每二次方秒、角速度为弧度每秒、力为牛顿。四元数顺序为 `[w, x, y, z]`。

## 成功与恢复

只有任务成功谓词全部通过的场景才能进入写入流程。全部帧、索引、元数据和 `complete` 标志在同一个 LMDB 写事务中提交。发布前执行深度校验和 compact；断点续采只统计通过快速校验的最终 LMDB。
